## 先解决的问题

使用同一个合法、固定版本的小样，以 Blender/MPFB 为参考，比较两种 Rust 执行路径：

- **A：离线编译人物包**，保留显式参数、node/mesh/primitive 绑定及必要的骨架规则。
- **B：源数据运行时**，优先使用 Humentity 已有加载、形变和骨架拟合能力，验证实际缺口后再改动最小部分。

共同小样先选一个 hm08 基础、一个简单 GameEngine deform rig、一件 `female_sportsuit01`，以及躯干比例和下巴局部各一对 target。选定文件名来自固定上游树元数据，参数范围、实际包内容、坐标和形变质量都要取得字节后核查。数值参考可以用中性材质；完整皮肤、眼睛、头发和动漫审美不由这个几何小样代为通过。

## 取得批准后的顺序

1. 只取得批准清单内的文件，校验已发布哈希或 Git blob 身份。系统包先重查长度、修改时间与 ETag；变化则更新请求。保留原包并建立本地 SHA256。
2. 在隔离目录检查归档路径、包内许可、实际所选文件与服装引用。将源码、许可证、原始数据及派生结果分开。缺失或不符时停止使用该项。
3. 实际启动固定 Blender/MPFB，明确 helper/拓扑、参数、坐标和 GameEngine rig，生成共同中性、身体、脸部和组合参考。先冻结输入与参考 manifest、误差单位及容差，再运行两条路径。
4. B 使用源码清单取得固定文件，而非默认获取含 LFS 资产的完整仓库；最小打包改动、派生 manifest/lock 和任何新增依赖分别有记录。先离线解析，缺依赖先列确切新请求。
5. 对比顶点、关节、inverse-bind 和衣物，再做连续编辑、抬臂/屈肘/屈膝、实际桌面/Web、CLI 数值与保存交换。构建、启动、功能、画面、质量、性能分别记结果。

该顺序落实后再决定 A、B 或保留数据补小缺口。两配方混合的 agent 创作实验仍属于人物基础准入后的下一阶段。旧 fixture 及实验不改写，现有真实动作质量 HOLD、#3 阻塞和 #4 缺口保持原状。
