# 同样本 Rust A/B：数值结论与下一道门

本轮已经证明：**可以复用 MakeHuman/MPFB 的真实人体数据，在 Rust 中连续调整身体与局部脸部，并让关节位置和衣物跟随。** 这支持继续复用成熟人体基础。它还没有证明完整捏人系统、动画质量或三端产品集成已完成。

## 实际对照

三项使用同一冻结 manifest `2e8566a4f12de710ead88f6aa2d71fc44e0680761a4f2fdc48a844b6f3534ab7`，同一 MPFB 2.0.18 参考、8 组配方、19,158 个原始身体顶点（含 helper）、53 根骨骼和 1,797 个原始衣物顶点。数值容差在全样本运行前固定为每个米制坐标分量 `1e-5`。

| 路径 | 实际计算 | 身体最大分量误差 | 衣物最大分量误差 | 骨骼范围 | 结论 |
|---|---|---:|---:|---|---|
| A：源数据编译为小人物包 | 自有 Rust sparse target、helper 端点、衣物 proxy 求值 | `3.808e-7 m` | `3.012e-7 m` | 53 组头/尾端点，最大 `2.540e-7 m` | 八组数值通过；无完整 rest/逆绑定/蒙皮实现 |
| B0：已有 Humentity 原算法 | 实际候选加载器、形变、helper、网格与骨架拟合 | `9.002e-4 m` | `7.946e-4 m` | 53 个头部位置通过；尾端点不公开，完整矩阵一致性未比较 | 改参数后数值失败，保留非零比较退出码 |
| B1：单行阈值对照 | B0 基础上只把小形变过滤阈值 `1e-6` 改为 `0.0` | `<4.06e-7 m` | `<7.59e-6 m` | 同 B0；实际 rest/逆绑定已输出但未验证其坐标系一致性 | 八组同容差通过；明确为修改后的候选 |

B 使用 UV 拆点后的实际网格，身体 22,077、衣物 1,986 个网格顶点，按候选输出的原始顶点 ID 比较全部源顶点覆盖；没有假定渲染顶点数必须等于源 OBJ 数。

B0 丢弃的小 target 行能解释所有八组身体/helper 误差，扣除后的最大残差约 `4.06e-7 m`。再用隔离 B1 实际重跑，身体与衣物均回到预定容差。原始源码、B0 二进制、八组输出及失败报告都保留；没有放宽容差、换样本或删除失败案例。B1 的比较报告标记 `candidate_algorithms_changed: true`。

## 推荐下一步

**优先让 B1 进入下一轮骨架/姿态准入实验，A 保留为独立对照。尚不把 B1 加入主线依赖。** 原因是现成 Rust 库已经执行网格、骨架拟合及逆绑定输出，主要形变误差可以由一个很小、已验证的改动解决。复用它有机会少维护一套完整人体运行时。

取舍是 B 仍有打包、单位/格式适配与浏览器目录加载问题。A 的数值路径更小、更明确，但完整骨架、蒙皮和显示仍需补建。当前结果足以选择**先验证哪条**，不足以作最终生产选型。

下一片保持同一小样和参数范围：

1. 核对 53 根骨骼的局部坐标系、rest/逆绑定和权重语义，不把端点吻合当成完整骨架正确。
2. 对抬臂、屈肘、屈膝做真实蒙皮参考；检查衣物跟随、穿插和法线。不给新 rig 套用旧 fixture 的动作准入结论。
3. 在隔离桌面/Web 原型显示同一参数与姿态，再做 CLI 数值、全作品保存交换、错误恢复和有界大小/时间/内存检查。浏览器目录读取必须实际解决并验证。
4. 通过这些门后再选择一条正式后端、收束另一条；随后扩展宏参数、脸部能力和目标审美。两张参考图自动捏人或任意动漫融合仍未实现。
