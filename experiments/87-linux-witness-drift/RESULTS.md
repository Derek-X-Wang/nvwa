# #112 离线数值归因

2026-10-22。**现有帧已足以解释面积比差异如何产生；仍不足以确定骨架矩阵为何不同。**
本轮不改原断言或门禁，不新增 CI 运行，不调整 Linux/macOS 分工。

## 已证实的直接原因

目标为 torso=+1、jaw=0、`b1_arm_rehearsal_v1` 的 2 秒姿态。肩部显示三角面 200
对应有序源顶点 `[246, 244, 182]`。只用这三个真实顶点即可重现原失败信号。

| 输入 | 静止面积 m² | 姿态面积 m² | 面积比 |
| --- | ---: | ---: | ---: |
| 历史报告及两个 Mac current19 帧 | 0.00001884345974021258 | 0.0004146623110947154 | 22.005635738420796 |
| Linux CI 实际帧 | 0.00001884345974021258 | 0.00041466291597743203 | 22.005667838827247 |

两份 Mac 帧都通过原 `22.0056357384`、`places=6` 的数值断言。Linux 帧仍失败，
与原断言值相差 `0.00003210042724788309`。原完整控制再次运行：18 项中同样 2 项失败。

完整衣物的拓扑、源索引、静止坐标及全部权重值/顺序完全一致，面积分母相同。
独立核对的身体数据也完全一致：22,077 个源索引及静止顶点、68,676 个索引值，
身体静止坐标最大差为 0 米；这仍不覆盖快照中未单独保留的 helper/骨骼端点中间值。
姿态面积分子相差 `6.048827166146159e-10 m²`。核心九个坐标分量中七个在实际
`f32` 位模式上不同，不能用同一浮点数的不同 JSON 小数写法解释。

按现有源代码的运算顺序建立离线 `f32` 模型：逐次舍入权重归一化、加权骨骼矩阵累加
及顶点变换。保持 Mac 静止坐标和权重不变，只替换成 Linux 保留的骨骼矩阵：

- 重放 Mac 矩阵，九个输出坐标逐个精确等于 Mac 实际上传坐标。
- 仅替换为 Linux 矩阵，九个输出坐标逐个精确等于 Linux 实际上传坐标。
- 面积分子、分母和比值也全部精确重现 Linux 结果。

因此，**保留的骨骼矩阵差异足以解释本例完整标量差异**。这是离线反事实重算，
不是一次新的 Rust 执行，也不证明模型对应某台机器的具体指令。

## 最早能观察到的差异

骨骼名称和父子顺序一致，但差异在静止骨架和逆绑定矩阵中已经出现，早于最终蒙皮累加。
这些矩阵描述骨骼静止时的位置及从静止空间转换的方式。

| 快照字段 | 有差异的骨骼 / 53 | 最大矩阵分量差 |
| --- | ---: | ---: |
| `inverse_bind` | 41 | 0.0000005960464477539062 |
| `rest` | 41 | 0.0000007152557373046875 |
| `local_rest` | 52 | 0.0000007152557373046875 |
| `posed` | 51 | 0.00000095367431640625 |
| `skin` | 52 | 0.0000007748603820800781 |

`inverse_bind` 的 379 个分量、`skin` 的 553 个分量有不同 `f32` 位模式。
已观察的权重顺序完全一致，不能将本例归因于蒙皮权重的无序遍历。

快照未保留原始骨骼端点、helper 向量、参考局部 Transform/四元数及各中间分解结果。
因此现有帧不能定位最早发生差异的算术指令，也不能区分目标平台运算、依赖特性组合
或生成器此前的状态历史。不能直接归因于 Linux、x86、SIMD、FMA 或某个库缺陷。
