# One static shoulder refit of the existing sportsuit

**Actual result: [blocked before authoring](RESULTS.md). The single Wasm input
attempt failed admission; candidate count is zero.**

This experiment attempts one independently identified rest-shape asset for #80.
The original garment, historical captures, old corrective candidates and product
assets remain unchanged. It does not add a runtime correction or a clothing
physics system.

## What may change

Only MHCLO offset tokens on the frozen connected 30-source shoulder panel may
change. The original OBJ, topology, UVs, signed mapping coefficients, full skin
weights, material and body-deletion mask stay exact. Editing OBJ positions alone
would be ineffective: the production fitter replaces them from MHCLO mappings.
The new asset must have its own manifest and eventual Work identity.

`geometry-policy.json` freezes the mathematical policy before results. The field
is authored from the original neutral helper cage only. All 581 local plane
constraints contribute to one amplitude interval. The author chooses its lower
endpoint once, reparses the saved offsets and checks the fixed residual floor.
There is no amplitude sweep, direction retry, support growth or score-driven
tuning. An infeasible attempt remains rejected.

## Inputs and admission

The original eighteen historical gzip arrays are missing. Their original hashes,
fixtures, source guards and authenticator are retained. Reports cannot replace
those arrays. A new capture is a new cohort, never recovered historical evidence.

The bounded replacement attempts are:

1. `replay/main.rs`: the current production CPU runtime, with no window, renderer
   or GPU. Eighteen original legacy-profile recipe slots plus the unchanged
   authenticated Web anchor form a proposed new hybrid cohort. Its actual native
   attempt was rejected by exact full-bone overlap admission. No candidate was
   generated from that failed corpus.
2. `wasm-replay/lib.rs`: one same-target CPU-only browser Wasm replay. It uses
   production asset loading and the public snapshot path, with the same legacy
   profile, commands, paused manual clock and eighteen requests. It installs no
   renderer or window runner. It is input collection, not visual acceptance.

`replay/collect_wasm.py` uses a distinct target/build/transport identity. It does
not fall back to native data. Both collectors preserve raw producer JSON without
numeric reserialization and use the same source, full-weight, exact fixture and
original-anchor gates. Failure of this single Wasm attempt stops this run before
authoring. See [the Wasm receiver contract](replay/README-wasm.md).

Before reading candidate bytes, the evaluator must independently reconstruct all
original body and garment rows in all nineteen slots. It follows the production
ordered f32 fit and stored-morph round trip. Rest errors must be <=1e-7 m per
component. Separate source/FK/binary64 LBS and scalar-f32 matrix-blend checks must
each be <=1e-5 m per component, including the original anchor. Neither check is a
claim of actual candidate upload parity.

## Decision order

Completed build provenance → admitted complete corpus → all19 baseline preflight
→ root's single authoring receipt → one frozen asset → all19 position evaluation.

The execution receipt pins every imported local Python helper as well as source,
build, artifact and corpus identities. Authoring and scoring reject changed or
incomplete receipts. A different output directory does not authorize another
candidate; the integrator owns the one-attempt limit.

Only an offline positional pass permits actual candidate Web A/B and CLI
save/reload. Generated normal/tangent closure and actual upload must be verified
there. Positions copied for analytical bookkeeping are not new shading output.
No result here certifies arbitrary clothes, complete collision freedom,
continuous poses, desktop UI, GPU performance or general clothing quality.

## Checks

From the repository root:

```sh
python3 -B scripts/check-portable.py shoulder-rest-refit
```

This runs both Rust hosts' formatting and replay, evaluation, authoring and client
controls in normal and optimized Python. Node is required for the actual client
lifecycle controls; its absence fails. These short controls use synthetic inputs
where documented. They do not substitute for actual nineteen-case evidence.

If the retained original source-proof directory is available, set
`NVWA_SHOULDER_RETAINED` to it before running the command. This enables the actual
old rejected crossing witness and the disabled-predicate red control. Otherwise
that witness is explicitly skipped. The ordinary historical and product gates
remain unchanged.

Actual baseline/scoring interfaces are documented in
[evaluation/README.md](evaluation/README.md) and the collector READMEs. They
require authenticated local inputs and a create-only output directory. Do not
replace required hashes or fabricate a PASS receipt to run them.

`build-wasm.py` runs locked offline Cargo and the already installed pinned
wasm-bindgen. It records the actual frozen build input closure before and after
compilation and the exact output artifact hashes. The parent supplies the real
wefty run identity. There is no tool or dependency installer in this experiment.
