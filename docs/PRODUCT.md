# Nvwa：产品定位与职责

确认：2026-11-04。本文件记录产品方向；当前交付以 [roadmap](ROADMAP.md) 和具体发布回执为准。

## 服务对象与职责

Nvwa 提供供外部 AI Agent 操作的人物与动画工具。用户选择 Codex、Claude Code 或其他 Agent；人可以观看、直接编辑并提出意见。

| 参与者 | 负责什么 |
| --- | --- |
| 用户与审核者 | 提供目标、照片和反馈，决定希望得到的作品与可接受的结果。 |
| 外部创作者（Agent） | 理解照片与文字、分解任务、选择操作、判断真实结果、决定下一次修正及何时请求澄清。 |
| Nvwa | 明确暴露能力和限制；执行人物、动作和舞台操作；提供与实际 Work、版本、视角和时间对应的观测；报告结果和错误；保留可继续编辑、保存与交换的作品。 |

Agent 的理解、规划、模型选择、上下文管理和自主循环由外部客户端拥有。产品能力应通过明确的操作和文件契约提供，避免绑定一个 Agent 品牌。示例或验收脚本可以演示使用方法，不成为产品内置的推理服务。

软件仍须有足够的表达能力。无法表达的轮廓、动作或相机需求应说明限制；Agent 不应被要求用无限调参补足工具缺口。保存的数值与画面均需核对，字段未变不能单独证明外观未变。

当真实创作反复需要同一项操作，把它接入项目自带的创作流程。让新的 Agent 能从能力说明找到入口，自助操作并核对结果。例如指定时间和镜头取图、量取像素距离、另存修改后按相同条件复看，均从 [CLI 创作流程](CLI-SUPPORT.md) 进入。

优先把可测量的场景事实作为结构化数据交给 Agent。动作检查应能按作品、部位和时间读取关节位置、脚底离地、支撑脚位移和片段边界，并标注坐标系、单位和采样条件。默认给简明结论和异常区间，按需展开对应的原始样本。回执应说明数据来自哪份 Work、如何复查，以及哪些结论只是推断。Agent 可以据此做局部修改，再用同一查询对比修改前后。数值检查应能独立于图像生成。把正面、侧面和正常速度播放用于最终视觉审核，判断人物外观、动作节奏和姿势是否自然。

## 值得建立并验证的优势

1. **领域操作明确**：创作者能发现并修改人物、动作片段、时间和舞台，不必每次重新组装底层场景操作。
2. **观察可信**：正常画面与实际作品身份、视角、时间绑定；可选辅助信息只有在帮助发现或修正问题时才保留。
3. **局部修改稳定**：保留未要求改变的内容，支持明确的失败、恢复和历史行为；同时用字段和必要的实际画面检验结果。
4. **作品可接力**：不同客户端可以操作同一份有版本、可编辑的 Work，人也可以接手审核和编辑。

这些是产品假设，尚不能宣称已优于其他系统。Three.js 已有[动画系统](https://threejs.org/manual/pages/animation-system.html)，Blender 支持[脚本与后台操作](https://docs.blender.org/api/main/info_tips_and_tricks.html)，Headshot／Character Creator 可将[照片人物送入动画制作](https://manual.reallusion.com/Headshot_Plugin/ENU/3.0/10-Save-and-Export/Exporting-iAvatar.htm)。CLI、JSON、可自动化或“Agent Native”名称本身不构成比较优势。

用少量相同创作及修改任务比较完成质量、人工介入、意外更改和首次／后续修改成本。对观察与修正流程，记录 Agent 为完成任务消耗的上下文或 token、调用次数和是否能独立定位、修改并复查。允许基线使用成熟组件，记录不同准备条件，不能从不对等设置推出胜负。复用更好的现成方案；不为一次比较建设大型评测平台或另一套渲染器。

## 当前交付与下一阶段场景

现有共享 Work、命令核心、Web／桌面／CLI、版本化人物控制、多段预制动作编排与自助多帧审看是起点。[#138 最终回执](https://github.com/Derek-X-Wang/nvwa/issues/138#issuecomment-6649825644)记录最新审看交付；静态样本不证明整段流畅或完整人物质量。

下一阶段用照片参考与动作要求检验工具：外部 Agent 解释参考、选择数值与动作；Nvwa 使它能够创建人物、审看关键视角、定位片段、局部修改并保存作品。照片相似度、跑步和短舞蹈是待验收的使用场景，不能写成已经支持的照片重建或任意文本动作生成。相似度目标及动作来源须在每阶段开始时说明。

参考照片及可识别人物的作品／渲染按用户许可保存和分享，默认不进入公开代码库。公开任务回执使用获准证据或不含身份资料的摘要；私有参考不构成自动公开授权。

长期 Goal 的可复制正文见[阶段计划](goals/agent-operated-character-animation.md)。保存计划不等于启用 Goal，也不改变旧 HOLD、资源授权或 CI 政策。

## 后期游戏嵌入边界

游戏或世界由宿主提供，Nvwa 的方向是提供人物定制、人物状态和动作能力。Honey Select 式方便捏人、查看人物并进入世界游玩的体验是参考方向，不是已交付的完整游戏范围。

- 当前保留 Work／命令的领域语义，与窗口、渲染对象和外部 Agent 的规划职责分开。现有依据见 [ADR-0005](adr/0005-portable-document-and-commands.md)。
- 之后选择一个具体宿主验证游戏内修改、保存和动作播放，再决定实际集成接口；不预先承诺任意引擎兼容。
- 资产导出、独立 Player 和真正运行时嵌入分别验收。已有 Rust 核心不等于已有 SDK。
- 当前阶段不建设跨引擎 SDK、通用 FFI／插件平台、世界编辑器或多人服务器；只有真实创作任务需要时才增补最小接口。
