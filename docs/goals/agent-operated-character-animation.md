# Nvwa：外部 Agent 可操作、可观测、可修正的人物与动画工具

## 目标与职责

持续建设供外部 AI Agent 使用的人物与动画工具，用照片参考创作、动作编排和局部改编证明它可用。用户选用 Codex、Claude Code 或其他 Agent；人主要观看、审核、反馈，也能直接编辑作品。

外部 Agent 负责理解照片和文字、分解任务、决定参数与动作、看图判断和选择下一步。Nvwa 负责能力发现、人物／动作／舞台操作、实际结果与错误、可核对的真实观测，以及可继续编辑、保存和移交的 Work。软件不承担内置 Agent、规划器、对话服务或指定模型的开发。

产品方向以 docs/PRODUCT.md 为准。照片理解是外部 Agent 的工作；足够的人物表达能力、明确的参数作用和可用观察是 Nvwa 的责任。动作选择与创作判断由 Agent 决定；支持的动作、播放、编排和修改行为由软件保证。

## 起点与阶段终点

先核对最新 main、README、GLOSSARY、roadmap、相关 ADR、#138／PR139最终发布证据和本对话最新授权。复用共享 Work、CLI／Web、人物控制、多段编排与自助审看。上一轮两个合格首稿已接受、实际有效创作修订为0；保持原始结论，不重新要求它们制造问题。

长期终点：用户提供同一人物的一组参考照片和动作意图，外部 Agent 能通过公开工具创建可编辑人物，使用实际支持的跑步与一种短舞蹈完成短作品，自行观察、修正，并按新的反馈另存改编。人能打开、查看和继续编辑；工具不依赖主会话代操作或某一个 Agent 品牌。

照片场景先验收关键外观特征可表达、可观察、可修正，不承诺照片级重建、任意衣发复原或全身精确测量。动作场景先验收明确的跑步与一种短舞蹈，不承诺任意文字生成任意动作。每个场景开始前固定参考、目标、可用来源及接受标准，不用字段或截图成功代替视觉结果。

## 阶段0：确定路径和缺失授权

核查当前工具与作品的实际能力，建立一条主线和至多一条有明确主线收益的独立副线。优先解决正式人物的可用动作；照片参考的表达与修正可在不争用资源时并行。

复用获准本地素材和现有工具；遇到能力缺口，先有界阅读官方文档、开源实现和现成方案。每个主要缺口最多比较两种实质不同路径，给出采用依据和停止条件。一次研究不超过20分钟；重要冲突可请 Astra 作一次不超过10分钟的判断。不能把同一失败不断拆成新的前置研究。

一次性列出阻塞当前阶段的素材、模型、依赖、资源及旧 HOLD 权限。未批准的输入不获取，未解除的 HOLD 不恢复；继续已批准且不依赖这些条件的独立项。缺少用户照片时先推进动作或工具任务，照片验收保留 NOT-RUN，不以自选照片冒充用户输入。

完成：确定可执行路径、每阶段首个验收案例、实际缺口和授权边界。不存在可推进的已批准项时准确停止并报告，不空转。

## 阶段1：正式人物的可用动作与编排

在明确获准的来源和范围内接入或制作动作，先让正式人物完成跑步或一种短舞蹈，再交付第二类。新增单个动作是中间里程碑，长期 Goal 不因此完成。保留来源身份，区分预制、导入和真正模型生成动作。

外部 Agent 能发现动作及适用人物，添加、组合、排序、重复、修改时间与速度，并播放、定位、保存和重开。复用现有能力，只有真实场景缺口才增加人物、动作、局部编辑或必要格式适配；保留旧 Work、命令、历史与版本边界。

对默认人物先验收，再选一个受支持的已编辑人物验证。检查动作可辨认、受检衔接、开始／结束、重复及接触问题；实际播放证据与指定时间静态图分别记录。局部通过不解除完整人物、衣物或 M2 质量 HOLD。需要触及停放依赖时先执行下方保留边界。

完成：两类明确动作在正式人物上可用；独立 Agent 自行交付20–30秒编排、审看和保存；正常 Web／CLI 交换及独立动作审查通过。来源不足或质量未过时保留 PARTIAL，不把旧样本或数值结果包装为交付。

## 阶段2：照片参考下的人物操作与修正

由独立新上下文 Agent 从用户提供或单独批准的参考照片提出可检验的外观目标，自行发现人物能力、创建作品、固定有用视角并取得真实图。Agent 自行分析参考；Nvwa 不新增照片理解模型或内置推理流程。

参考照片及可识别人物的作品／渲染默认留在本地私有证据中；公开分享须核对用户许可。未获公开许可时交付私有作品与证据，并发布不含身份资料的状态说明，不把公开用户人像设为完成前提。

有实际表达缺口时，允许开发最小必要人物控制、明确版本、操作或观测能力，先确定控制真实作用及限制，再接入产品；不能只给参数改名。任何新素材、依赖或模型需求仍按授权规则处理。

至少完成两部不同目标的人物作品，分别保留参考使用范围、实际 Work、操作及正常图。独立评审先看正常图和目标，再核对身份／字段，披露非盲限制。只有存在真实问题时才修正；首稿合格可以接受。新的改编要求是新需求，不冒充修复收益。每例最多两次同类修正，仍未通过则停放该例，不换案例或评委凑通过。

完成：至少两部作品的明确局部外观目标获独立接受，Agent 可自行观察和局部修改，未要求改变的设置经字段与必要画面核对保持；未支持的相似度和外观要求有清楚边界。

## 阶段3：完整创作与局部改编

用新的独立创作者完成至少一部同时包含照片参考人物、阶段1动作和舞台设置的20–30秒作品。只提供目标与公开工具说明，不预给参数和完整编排答案。Agent 自行首次查看及修改后复看，主会话不代操作来满足自助条件。

接收一条明确的新反馈，例如调整中段动作节奏、保持人物与镜头。另存版本，验证目标实际成立、未要求改变的内容得到保留。原稿合格无需制造缺陷；按反馈改编不自动等于质量提升。

真实执行正常 Web打开／保存、独立 CLI校验／修改／保存、正常文件选择器 Web重新打开并保存；核对实际文件字节和观测对应的 Work、版本、时间与相机。使用至少两个独立创作者上下文；若现有可用客户端允许，覆盖两个不同 Agent 客户端。单客户端证据不得宣称跨客户端验证，不为测试绑定某模型建设专用业务入口。

完成：独立 Agent 无主会话代操作地交付原作与反馈版本，人能正常查看、重开和继续编辑；按已获许可交付可编辑作品、必要渲染原图、命令、中文说明、来源与限制，独立审查接受实际结果。

## 阶段4：验证工具优势并收束

针对一项完整创作和一项局部修改，使用相近任务、资产权利、Agent能力和资源条件，与一个合理搭建的 Three.js 或 Blender 流程作小规模对照。允许基线复用成熟组件，分别记录初次准备与后续修改成本；不采购软件或建设大型评测平台。

记录作品质量、人工介入、意外更改、首次及修改交付时间和条件差异。使用已有可运行条件；若公平基线需要新增安装、素材或额度，记录 NOT-RUN和所缺授权，竞争优势保留“未证明”，不能以设计主张或单次胜负冒充结论。

完成：形成有实际证据的优势、短板和下一优先项；未做或不可比的对照准确报告。产品交付与比较实验分开，比较缺证据不抹去已交付功能，也不允许宣称竞争优势已验证。

## 架构边界：为游戏嵌入留位置

保留人物与动作领域语义、可移交 Work、命令与播放逻辑同窗口／渲染适配／外部 Agent规划的边界。已有共享 Rust 核心不等于已交付 SDK；资产导出、独立 Player 和实际运行时嵌入分别验收。

本 Goal 不实现世界、多人、游戏玩法、跨引擎 SDK、通用 FFI／插件／MCP平台。未来选择一个宿主验证游戏内捏人、保存和动作；当前只避免把人物业务硬绑某个 Agent 或编辑窗口，不为未来假设重构现有内核。Honey Select 式创作与游玩体验作为方向，不扩展为本轮完整游戏要求。

## 执行、审查与发布

持续使用 sub agents，明确开发、独立创作和独立审查的写入与图形归属。重要范围内判断、冲突或两次同类失败可用 Astra 一次有界判断；它不能代替用户批准新权限。任何时刻至多两项重编译、一项图形任务。按当前有效仓库指令和工具规则执行长检查、后台任务及资源管理。

阶段通过后在同一 Goal 内自主推进下一项已批准任务，不为每个小功能重新建 Goal。每阶段开始写明一项可见成果与验收；完成一阶段不足以标记长期 Goal 完成。出现重要范围决定、连续两次同类失败无新证据、资源越界或需解除 HOLD 时保存证据，切换已批准独立项；无独立项可做则准确停止。夜间遵守仓库 dark-factory 规则，不能等待人类答复。

先保留旧断言、快照、上下文及失败，运行相关 Web／CLI 验收、受影响测试、必要 native／Wasm 编译和独立审查。普通桌面 UI 按大版本策略记 NOT-RUN；桌面专属修改专项验证。辅助观测仅在证明事实到操作收益时保留，正常画面始终作为视觉判断依据。

开发与发布在隔离 codex/分支；本 Goal 明确启用后，范围内提交／PR、现有正常免费 CI、独立审查通过后的普通 squash merge及自然 main验证可自主完成。核对目标、精确head、审查树、完整workflow结论与必需作业实际SUCCESS；必需SKIP不算通过，可选warm只允许原条件SKIP或实际SUCCESS。合并后验证tree和父提交，只使用自然push mainCI，main通过才算该阶段发布完成。API未知或观察超时不等于CI终止；复用原run，不启动重复观察器。

普通真实功能错误可在原范围有界修复、独立复审后用实质新提交验证。main失败先保留日志并停发布，不能无变化重跑、自动回退／追加提交或把未验证main当通过。预算耗尽、需改runner／缓存／门禁／验证框架立即停止受影响发布并找用户；不得拆作业、删弱测试或循环加时。健康等待安静，按用户偏好每30分钟核查；具体CI留在当前任务跟进，不新建追踪单次任务的自动化。

现行预算以仓库实际政策为准：portable25／eye-hair10／native75／B1与warm60分钟；若核对有冲突，不自行放宽。现有固定Rust／Wasm／Cargo.lock获取与正常免费CI授权保留。新模型推理或服务、新素材／大型源码获取、新依赖版本、额外机器、付费资源及预算政策均需单独授权；启用Goal不隐含批准这些。

## 长期完成条件

1. 外部Agent和Nvwa职责明确，公开操作和文件契约不绑定指定Agent或模型。
2. 正式人物的跑步与一种短舞蹈具备独立实际验收及完整编排／保存支持。
3. 至少两部照片参考人物作品达到事先说明的局部外观目标，表达与观察限制如实保留。
4. 至少一部完整照片参考人物动画及其新反馈版本，由独立Agent自行操作、审看和交付；无需制造修订来凑次数。
5. 正常Web／CLI交换、未请求内容保留、失败恢复、独立审查、相关测试编译与每个发布阶段的PR／自然main验证齐全。
6. 小规模对照有结果或准确NOT-RUN／不可比记录，竞争优势只按实际证据表述；源码、作品、说明和路线图可接力，资源清理完成。
7. 游戏嵌入只保留架构边界；旧HOLD和未验收能力未被改写成通过。

只有上述交付与证据全部满足才将长期Goal标记complete。未获必要授权的终点场景保持PARTIAL；不把一份设计、一个动作、一个脚本或一个合并当成长期完成。
