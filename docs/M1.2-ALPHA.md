# M1.2：离线 CLI agent 创作与 Alpha 交接

## 支持范围

创作 agent 运行在外部工具 session，Nvwa 提供 Rust CLI、Work 和相同领域命令。当前闭环是文件创作→Studio 重载→继续编辑→Player 播放。作品中的 idle/wave/turn 是 authored actions。

本轮复现环境为 macOS arm64，Web 使用具备 WebGPU 的受测浏览器。原生/Web 的编译、启动、功能与性能分别登记；公开二进制、额外平台、签名/公证、真实模型推理及实时 Studio bridge 属于后续门。

## 1. 构建 CLI 并发现能力

从检出本提交的仓库根目录运行：

```sh
CARGO_TARGET_DIR=.work/m12-alpha-build cargo build -p nvwa-cli --locked
mkdir -p .work/m12-alpha
./.work/m12-alpha-build/debug/nvwa-cli new assets/character.profile.json .work/m12-alpha/initial.json
./.work/m12-alpha-build/debug/nvwa-cli describe-capabilities .work/m12-alpha/initial.json
```

使用本任务自己的构建目录，避免依赖已有 `target` 链接或其他 session 的构建状态。工作目录已存在时先检查其中的文件；不要覆盖别人的 Work。读取 `character_id`、`document_revision`、参数范围、动作时长与 `cli_contract`。命令写法、revision、会话边界和响应错误恢复见 [CLI 指南](agents/cli-authoring.md)。

## 2. 实际 agent 与可重复重放

真实 agent 的验收任务、决策、原始调用及修复前后边界见 [实验38](../experiments/38-agent-cli/REPORT.md)。录制来自实际原生 agent session；保存的进程记录核对器不独立证明 LLM 作者身份。

以下是确定性重放，使用已录制的命令文件，单独标为重放：

```sh
./.work/m12-alpha-build/debug/nvwa-cli apply .work/m12-alpha/initial.json experiments/38-agent-cli/appearance.commands.json .work/m12-alpha/appearance.json
./.work/m12-alpha-build/debug/nvwa-cli apply .work/m12-alpha/appearance.json experiments/38-agent-cli/stale-timeline.commands.json .work/m12-alpha/rejected.json
```

第二条预期 exit1、`revision_conflict`，且不生成 `rejected.json`。先读取真实状态，再使用录制的修正请求：

```sh
./.work/m12-alpha-build/debug/nvwa-cli inspect .work/m12-alpha/appearance.json
./.work/m12-alpha-build/debug/nvwa-cli apply .work/m12-alpha/appearance.json experiments/38-agent-cli/corrected-timeline.commands.json .work/m12-alpha/authored.json
./.work/m12-alpha-build/debug/nvwa-cli validate .work/m12-alpha/authored.json assets
./.work/m12-alpha-build/debug/nvwa-cli save .work/m12-alpha/authored.json .work/m12-alpha/final.json
./.work/m12-alpha-build/debug/nvwa-cli inspect .work/m12-alpha/final.json
python3 -B experiments/38-agent-cli/verify.py
```

预期 final：revision2、jaw_width0.42、smile0.2；idle0–3s、wave3–6s、turn6–9s。速度按源动作时长调整。`validate ... assets` 需要 `asset_checked:true`。核对整份文档，而非只比较两个参数。

输入/命令失败和响应传输失败是不同边界。如果收到 `stdout_write`，作品可能已经保存；先 inspect 输出再决定是否重试。外部中断或无法投递 stderr 也不能作为“没有保存”的证据。进程间没有文件 CAS、持久幂等记录或共享 Undo。

## 3. Studio 继续编辑与 Player

首先按 [构建说明](../README.md)准备本地原生和 Web 产物；不要把不存在或过期的 `dist` 当成当前构建。实际本轮 GUI 使用的保留二进制、source cohort 和 SHA 单独列于 [双端证据](evidence/m12-agent-loop/REPORT.md)。CLI-only 修改与未修改的 Studio/runtime/core 需要逐文件比对后才复用 GUI 产物。

已有原生包时，Work 路径使用绝对路径：

```sh
./dist/Nvwa.app/Contents/MacOS/Nvwa --work "$PWD/.work/m12-alpha/final.json"
./dist/Nvwa.app/Contents/MacOS/Nvwa --player --work "$PWD/.work/m12-alpha/final.json"
```

Web 启动方式以当前仓库的静态服务器与 Web 构建说明为准；用文件选择器 Open 上述 final Work。Web 资产与 profile 中的相对路径及 hash 必须一致。原生目录结构和 Web 文件选择/下载分别处理。

Studio 中改一次 jaw width，保存；当前会话 Undo 后再保存，应恢复内容并保持 revision 单调递增。重载不会带回 CLI 或上一 GUI 会话的历史。Player 应显示同一真实角色和九秒编排；暂停后点击角色触发一次 wave，再恢复原播放位置/状态。
