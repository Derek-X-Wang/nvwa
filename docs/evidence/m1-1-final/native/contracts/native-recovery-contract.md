# Native recovery and whole-Work contract

Contract only. Root owns real native GUI execution, private bundle setup, observations and result claims. Worker did not run tests, GUI, GPU, Cargo or the native binary.

## Verified source semantics

- Studio toolbar sends its Work text verbatim to native request_open/request_save (crates/nvwa-studio/src/lib.rs:599, 903, 905). Native Open uses std::fs::OpenOptions.open(path); it opens no chooser. A relative Work path uses process working directory, so enter absolute Work paths in the GUI (platform.rs:181-208).
- GLB asset_path does not use the Work file's parent. native_asset_root chooses NVWA_ASSET_ROOT first; otherwise executable.parent()/../Resources/assets if that directory exists; otherwise compile-time CARGO_MANIFEST_DIR/../../assets (lib.rs:251-263). AssetPlugin receives that root (lib.rs:88-91). Leave the private bundle Resources/assets directory present. The default case assumes no NVWA_ASSET_ROOT override in the actual launched process; root uses Cua for the native launch. This worker does not inspect or alter process environment.
- Every successful Work Open replaces Editor and increments internal document_generation, including identical JSON/path (runtime/lib.rs:43-48). Input document revision stays 1. Loading a new generation despawns prior root and resets ready/error. Same-path generation waits for retired root completion and AssetServer cache removal before issuing fresh load (runtime/lib.rs:458-483, 638-704). Copying an asset alone is not an Open or proof of recovery.
- Missing GLB errors arise in AssetServer byte loading (Asset byte load failed...), not native Work file Open. Require the valid JSON Work to load first and the character error to be visible. Do not accept an absent Work-file error as a missing-GLB result.
- Interaction is temporary runtime state, never serialized or applied as a document edit (runtime/lib.rs:127-138). It requires original profile.id, original asset SHA-256, a nonempty timeline and wave mapping. Both prepared inputs preserve these. The rig, scene, skin and animation subassets remain in the copied original GLB; the SceneDocument schema has no rig/interaction fields to add.

## Whole-document comparison

Require the same key set at every object, every array entry in the same order and all listed fields in expected-manifest.json. Profile parameters retain IDs, morph indices, limits and defaults. All clip IDs, animation indices and durations remain. Character IDs, profile ID, all four shape parameters and scale remain. All three timeline IDs, clip IDs, starts, durations, speeds and looping flags remain. Schema version and revision remain exact. Strings and booleans remain exact; reject extra/missing fields.

Ignore JSON whitespace, object key order and equivalent number spelling. At f32 fields only, compare finite values after IEEE-754 binary32 conversion; require the exact same converted value, without an arbitrary epsilon. Integer fields stay exact integers and must not be treated as floats or booleans. Serialized byte hashes may differ while typed documents match. Runtime generation, playback position/playing/completed, active interaction, selection, pane sizes and editor history are outside SceneDocument; do not invent persistence for them. GUI interaction restoration must be observed separately from Doc equality.
