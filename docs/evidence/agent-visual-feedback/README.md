## 实际创作与修改

新上下文的 Sol agent 只收到自然语言目标、现有 CLI／素材路径和使用说明。
它自行查询能力，从零创建窄下巴、short01 人物、暖光深灰舞台及四段20秒编排。
举臂／抬膝均为现有预制动作，不是本轮生成的动作。

agent 请求第2秒真实预览并用图像工具查看。收到“脸和发际太小，另存近景，
其他内容不变”的反馈后，它自行选择相机，再请求并查看同一时间点的近景。
两版共13次实际 CLI／预览调用均 exit 0。独立 Astra 审查从新基线重放两组
命令，输出与两份 Work 逐字节相同，素材校验通过。

## 独立性与路由边界

第一轮 agent 自行打开浏览器并查看 PNG。第二轮它的浏览器工具返回空清单；
agent 保留仍在运行的预览命令和 URL，整合会话只代开这个相同 URL，没有重启
请求或选择相机。随后仍由作者独立查看 PNG、核对文件并报告。该轮证明了实际
AI 编排的创建／查看／修改／再查看，不能宣称第二轮单会话浏览器路由完全无人协助。
两轮没有人替作者写创作命令或操作控件。

## 预览入口与失败记录

入口复用生产 Studio、B1 加载／姿态发布和 Web 渲染。独立 Cargo example
目标保留原有 Studio 默认启动入口，不改运行时、schema、依赖或旧源码准入。
按[使用说明](../../agents/visual-preview.md)构建和请求预览。

适配器等请求 Work 实际提交后才暂停定位，检查已发布时间、相机和稳定状态，
等待真实渲染截图回调，再取得保持姿态的画布 PNG。这个 PNG 是回调之后的
画布帧，不是回调自身的图像。接收端要求匹配 Work、revision、有效相机／时间
和完整1280×720 PNG。保留原始数字，同时记录现有 Rust API 的精确 f32 值；
相邻 f32 值仍拒绝，不用宽松容差掩盖差异。

实际初次启动曾误拒绝尚未提交 Work 的外观状态，随后在新适配器内修正。
第二个问题是相机短十进制和提升后的 f32 JSON 表示不同；保留拒绝回执后，
按上述精确表示修正。失败记录和旧编译产物暂存本地，不改写为通过。

13项传输控制在普通和 `-O` 模式通过；真实命令分别拒绝旧构建、坏 Work、
非有限时间和已有输出目录，输入保持不变。另一次真实空 TCP 连接测试验证
服务按1秒期限失败退出，不生成成功图片。独立源码复审已核对这些修正。

## 普通 Web／CLI 交换与检查

普通 Studio 实际打开初稿，Play 后观察到 Replay20.0。通过正常文件选择器
打开近景 revision5 并 Save，实际下载与作者文件一致。CLI 校验、另存，再让
Web 先恢复不同的 revision4，随后用正常文件选择器打开 CLI 文件；等 revision5
近景提交后再次 Save，下载仍逐字节相同。当前源码新编译的 native CLI 也再次
验证了最终下载。见[交换回执](exchange.json)。

该普通 Studio 验收复用已有标准 Web 包：原273个宽指纹输入中270个不变，
另3个差异只涉及原有 policy/docs，实际 Rust／构建／素材源未改。新预览 example
有独立的新 Wasm 编译，不把它混作标准 Studio 新构建证明。普通界面操作的
底层工具截图及原始调用记录保留本地；公开 PNG 展示预览入口，不冒充保存操作截图。

本轮原生244项 workspace 测试、7项预览 example 测试、两次实际 Wasm 编译及
