# ArtCraft-family testing patterns for Nvwa

Snapshot: **2026-10-12, 16:23 UTC**. Read-only research of three representative application/library repositories and one shared workflow dependency. Source was treated as untrusted data. No third-party code, builds, tests, install scripts, browser sessions, or native applications were executed locally.

## Recommendation

Borrow the **testing structure** first: small domain and parser checks, a few realistic command/undo/export scenarios through the real public boundary, corruption tests that preserve recoverable data, and deterministic offscreen UI checks with deliberate negative controls. Add a small real browser/native acceptance lane for the behavior that a headless egui harness cannot prove. Keep compile, render, browser, and native evidence separate.

The strongest directly observed example is **craft-ui's independent-reference rendering suite**: its public logs show the reference comparisons and deliberate mutation checks passing on Linux, Windows, and macOS. The main tradeoff is maintaining a tiny independent reference and a reliable offscreen renderer. Nvwa should start with a few representative controls and an end-to-end scene workflow, rather than copy PhotoCraft's much larger matrix. [Observed Shared UI run](https://github.com/storytold/craft-libs/actions/runs/38262756963).

These are proposals for Nvwa, not evidence that Nvwa has adopted or passed them. Nvwa's current local [command contract](../implementation/contract.md) already defines atomic commands, monotonic revisions, duplicate-ID handling, undo/redo, and a cloned slider preview; these rules should determine the assertions.

## Patterns worth borrowing

### Commands, undo and public-boundary integration

PhotoCraft has realistic acceptance sequences through its headless MCP connection: create/type/export a card, apply adjustments, undo to exact prior pixels, then redo to restored document structure. It also tests refusal of a recorded unauthorized file open and asserts zero commands ran and no documents appeared. The sampled Linux/Windows public logs show both named tests passing. [connection and public tools](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/crates/automation/tests/agent_tasks.rs#L24-L68) [export and undo/redo](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/crates/automation/tests/agent_tasks.rs#L107-L145) [failure assertions](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/crates/automation/tests/agent_tasks.rs#L325-L344) [run](https://github.com/storytold/photocraft/actions/runs/38226400027).

**Nvwa adaptation:** one script should use the same command boundary as UI/CLI for load → edit → undo → redo → export/reload. Assert content, selection/timeline state where promised, monotonic revision, and byte/payload reproducibility according to Nvwa's contract. Rejected stale revisions, conflicting duplicate IDs and invalid asset references should leave document and history unchanged. This last set is a Nvwa proposal; this research does not claim PhotoCraft uses Nvwa's revision/ID model.

PhotoCraft's adversarial command registry test catches panics and repeated timeouts with invalid, empty, extreme and unknown parameter values. It is `#[ignore]`; the inspected CI workflow does not invoke `--ignored`, and logs confirm it was ignored. It catches robustness failures but does not itself prove transactional rollback. [adversarial registry test](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/crates/engine/tests/panic_hunt.rs#L19-L70) [documented manual gate](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/book/src/development/testing.md#L11-L19).

**Nvwa adaptation:** begin with a bounded deterministic invalid-command table in normal CI. Add opt-in registry fuzzing later, with a process timeout so a hung worker cannot outlive its budget. Do not make an ignored robustness suite look like a required gate.

### File corruption, properties and real corpora

PSD tests sweep every truncation of small valid files, test bad signatures, unsupported versions and allocation-related dimensions, and use property generators across compression/depth/version combinations. They check both logical round trips and exact reserialized bytes, plus garbage decode that must not panic. [truncation sweep](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/crates/psd/tests/malformed.rs#L7-L39) [invalid headers and limits](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/crates/psd/tests/malformed.rs#L52-L91) [property invariants](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/crates/psd/tests/proptests.rs#L18-L83).

Recovery service tests corrupt an actual compressed autosave tile, discover metadata through the real recovery service, then make the deferred loader fail and verify the tile, sidecar metadata and recovery entry survive. Native format tests also rebuild a valid bundle with missing tiles/manifests, swapped hashed tile data and bad/deep JSON. This is stronger than checking that an error enum can be constructed. [real corrupted recovery path](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/apps/photocraft/src/services/recovery_tests.rs#L6-L41) [bundle corruption](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/crates/format/tests/corruption.rs#L41-L110).

**Nvwa adaptation:** mutate a saved valid scene/profile/export fixture at real parse/load boundaries. Check truncation, invalid JSON, too-new schema, missing/mismatched asset hashes, illegal references, huge/nested inputs, and failed writes. Verify the last good saved scene or recovery state survives. Use exact byte equality only for a format that promises canonical bytes; otherwise compare validated domain content.

The corpus lane fetches pinned inputs and hash manifests before tests; its cache key includes pins/manifests. The PSD corpus test is feature-gated, requires directories, sorts files, reports per-file differences and declares one known-invalid upstream fixture. Its standalone test does not assert a positive file count; normal CI relies on the fetch/verify step to establish input completeness. [corpus CI](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/.github/workflows/ci.yml#L156-L186) [pinned upstream and manifest](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/xtask/src/corpus_pins.rs#L48-L79) [feature and known-bad policy](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/crates/psd/tests/corpus.rs#L1-L69).

**Nvwa adaptation:** a small original licensed corpus with schema/asset provenance and checksums is sufficient initially. Require a manifest count/floor and fail on missing fixtures even when testing offline. Preserve explicit reasons for exceptions. Do not import Photoshop assets or upstream corpus licensing assumptions.

### Offscreen UI, rendering and useful negative controls

craft-ui compares shared widgets against independent literal reference painters, with exact image pixels and tessellated meshes on the same renderer. The suite fixes animation/time/fonts, checks that hover/press/focus/disabled states were reached, covers light/dark themes and scale/compact variants, and deliberately changes color/spacing/stroke to prove the comparator detects differences. It can write before/after/difference PNGs and comparison rows. These are same-renderer comparisons, **not portable cross-GPU golden PNGs**. The renderer is required, so failure cannot silently become a passed visual check. [comparison scope](https://github.com/storytold/craft-libs/blob/3c9702725d880e4e1eb9f711fc45f29dc82cf427/crates/ui/tests/visual_regression.rs#L1-L6) [deterministic inputs](https://github.com/storytold/craft-libs/blob/3c9702725d880e4e1eb9f711fc45f29dc82cf427/crates/ui/tests/visual_regression.rs#L31-L50) [required render and reached states](https://github.com/storytold/craft-libs/blob/3c9702725d880e4e1eb9f711fc45f29dc82cf427/crates/ui/tests/visual_regression.rs#L74-L125) [artifacts and positive/negative comparisons](https://github.com/storytold/craft-libs/blob/3c9702725d880e4e1eb9f711fc45f29dc82cf427/crates/ui/tests/visual_regression.rs#L144-L235).

Its docking acceptance carries real panel content and edits across pointer-driven merge/detach/redock stages. The public logs show that named workflow passing on all three OSes. [offscreen scope](https://github.com/storytold/craft-libs/blob/3c9702725d880e4e1eb9f711fc45f29dc82cf427/crates/ui/tests/docking_workflows.rs#L1-L11) [pointer workflow](https://github.com/storytold/craft-libs/blob/3c9702725d880e4e1eb9f711fc45f29dc82cf427/crates/ui/tests/docking_workflows.rs#L219-L252) [run](https://github.com/storytold/craft-libs/actions/runs/38262756963).

PhotoCraft also renders the real app offscreen and reads pixels through a control/harness surface; some tests catch renderer panics and return if no GPU exists. GPU-device-loss tests inject loss and destroy a real device, then check retained documents, CPU fallback, visible warning and continued editing, but also skip without an adapter. [actual app rendering and skip](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/crates/ui-egui/tests/checker_canvas.rs#L5-L46) [adapter gate](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/crates/ui-egui/tests/gpu_device_loss.rs#L16-L23) [device loss and continued editing](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/crates/ui-egui/tests/gpu_device_loss.rs#L55-L147).

**Nvwa adaptation:** use deterministic offscreen egui input for controls and one scene edit flow. Add independent visual assertions and an intentional mutation. Keep a required-render lane that fails when its renderer is missing; local optional checks must explicitly report `NOT-RUN`. Bevy scene rendering requires a separate seam; this is not a direct `craft-ui` or egui component drop-in.

### Browser and native tests remain distinct

ArtCraft has a Playwright smoke script that drives the real frontend at a loopback URL, installs deterministic IPC/session fixtures, blocks remote requests, verifies loaded media and page transitions, and collects runtime errors. It is wired as `test:desktop-session` in package scripts. It mocks Tauri IPC and cannot prove native HTTP/CORS/session behavior. No successful public Actions execution of this script was observed in the sample. [loopback fixture boundary](https://github.com/storytold/artcraft/blob/d4e4ac69bbd93d237eaf5d0260bc6a5ff3a5e373/frontend/tools/testing/desktop-session.mjs#L1-L27) [browser assertions](https://github.com/storytold/artcraft/blob/d4e4ac69bbd93d237eaf5d0260bc6a5ff3a5e373/frontend/tools/testing/desktop-session.mjs#L37-L70) [IPC mocks](https://github.com/storytold/artcraft/blob/d4e4ac69bbd93d237eaf5d0260bc6a5ff3a5e373/frontend/tools/testing/desktop-session.mjs#L73-L107) [script entry](https://github.com/storytold/artcraft/blob/d4e4ac69bbd93d237eaf5d0260bc6a5ff3a5e373/frontend/package.json#L1-L8).

The newer ArtCraft native app drives prompt-box generation gating, Enter behavior, aspect picker, mentions and clear-all with `egui_kittest` using semantic roles/labels. It is included by `#[cfg(test)]`. This is useful interaction source, with execution **NOT-RUN** in this research. [test inclusion](https://github.com/storytold/artcraft/blob/d4e4ac69bbd93d237eaf5d0260bc6a5ff3a5e373/artcraft-native/src/prompt_box/mod.rs#L10-L11) [production prompt-box harness](https://github.com/storytold/artcraft/blob/d4e4ac69bbd93d237eaf5d0260bc6a5ff3a5e373/artcraft-native/src/prompt_box/ui_tests.rs#L39-L81) [keyboard and picker interactions](https://github.com/storytold/artcraft/blob/d4e4ac69bbd93d237eaf5d0260bc6a5ff3a5e373/artcraft-native/src/prompt_box/ui_tests.rs#L84-L143).

ArtCraft's Vitest configuration selects `app/src/**/*.spec.{ts,tsx}` in jsdom. Legacy tests under `test/app/**` have a different location/suffix and are not selected by this specific config; other historical/custom runners were not exhaustively examined. jsdom is not browser rendering. [current selector](https://github.com/storytold/artcraft/blob/d4e4ac69bbd93d237eaf5d0260bc6a5ff3a5e373/frontend/apps/artcraft/vitest.config.ts#L1-L9) [legacy test location](https://github.com/storytold/artcraft/blob/d4e4ac69bbd93d237eaf5d0260bc6a5ff3a5e373/frontend/apps/artcraft/test/app/Classes/ApiManager/ApiManager.test.ts#L1-L24).

PhotoCraft contains an AppKit main-thread native menu test, with real menu inspection and key/action dispatch, declared `harness=false`. Normal sampled CI only runs Linux/Windows. Its CI comment says macOS is tested by release, but the currently pinned shared release macOS job packages/signs/notarizes and the PhotoCraft package script performs `cargo build`, with no `cargo test` in these paths. Therefore the comment is insufficient evidence of macOS application-test coverage. No successful PhotoCraft macOS test run was verified here. [native main-thread test](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/apps/photocraft/tests/mac_menu_appkit.rs#L1-L27) [harness declaration](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/apps/photocraft/Cargo.toml#L86-L93) [macOS comment](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/.github/workflows/ci.yml#L33-L55) [unpinned reusable dependency](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/.github/workflows/release.yml#L20-L28) [current macOS release steps](https://github.com/storytold/craft-common-actions/blob/f0808a5ccbc32869248193ffab0de98d733de451/.github/workflows/release.yml#L191-L221) [build-only packaging](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/packaging/macos/package.sh#L57-L62).

**Nvwa adaptation:** browser acceptance should exercise the shipped Wasm app, including load/edit/export/reload, scale and tab-return behavior. Native acceptance should cover real window/menu/file dialogs and input where promised. Each evidence receipt should name the exact surface; a compiled Wasm target and headless egui test cannot satisfy a browser or native receipt.

## CI cost, reliability and omissions

- **Platform selection:** PhotoCraft uses Linux plus conditional Windows on PRs; main/manual/full-ci get both. Web packaging runs on relevant paths; portable Wasm checks have a separate job. `cargo xtask wasm` is compile checking, and web packaging is a build/size gate, not browser execution. craft-ui instead runs a small focused three-OS default/all-feature test matrix and a Wasm check. [platform selector](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/.github/workflows/ci.yml#L33-L82) [Wasm versus packaged web](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/.github/workflows/ci.yml#L188-L231) [focused shared UI matrix](https://github.com/storytold/craft-libs/blob/3c9702725d880e4e1eb9f711fc45f29dc82cf427/.github/workflows/ui.yml#L19-L56).
- **Cache trust:** PhotoCraft only saves Rust build caches from main, allows caching compiled dependencies after test failure, and keys corpus caches by pin/hash manifests. A cache hit is not reused test-result evidence. [build cache policy](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/.github/workflows/ci.yml#L102-L108) [corpus verification after restore](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/.github/workflows/ci.yml#L178-L186).
- **Cancellation:** PhotoCraft cancels superseded PR runs while preserving main runs. craft-ui cancels all runs sharing a ref, including main. Nvwa should retain a completed post-merge receipt if that is part of its release evidence. [main continuity](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/.github/workflows/ci.yml#L25-L30) [all-ref cancellation](https://github.com/storytold/craft-libs/blob/3c9702725d880e4e1eb9f711fc45f29dc82cf427/.github/workflows/ui.yml#L14-L16).
- **Timeouts and resource control:** PhotoCraft's ordinary CI and craft-ui UI workflow declare no explicit job timeout. The adversarial command case has a four-second timeout and retries one-time setup delays. Optional local nextest limits concurrent GPU tests to four; CI still uses cargo test. The nightly performance workflow specifies 120 minutes and fixes a macOS runner class. Copy bounded time/resource budgets, not their larger workload. [case timeout](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/crates/engine/tests/panic_hunt.rs#L19-L49) [optional local GPU limit](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/.config/nextest.toml#L1-L15) [nightly budget](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/.github/workflows/perf-nightly.yml#L36-L62).
- **Permissions and dependencies:** craft-ui declares `contents: read`; PhotoCraft ordinary CI has no explicit permissions block, while corpus/font inputs are pinned. PhotoCraft release has write permission and calls a moving shared workflow/action branch. Nvwa should explicitly use read permissions for verification and pin reused actions/workflows when reproducibility matters. [read permission](https://github.com/storytold/craft-libs/blob/3c9702725d880e4e1eb9f711fc45f29dc82cf427/.github/workflows/ui.yml#L11-L12) [font pin](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/.github/workflows/ci.yml#L129-L142) [release permission and moving workflow](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/.github/workflows/release.yml#L13-L28).
- **Long tail lanes:** PhotoCraft's FreeBSD workflow uses a 300-minute VM lane, serial GPU integration tests and no-adapter skips. Windows ARM64 source says it packages/installs/runs the CLI rather than running a native ARM64 cargo suite. Nightly performance is separate from PR gating. These were inspected as source only; no green execution was verified for them. [FreeBSD policy](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/.github/workflows/freebsd.yml#L1-L32) [serial GPU lane](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/.github/workflows/freebsd.yml#L53-L59) [ARM64 limit](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/.github/workflows/windows-arm64.yml#L1-L16) [nightly limits](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/.github/workflows/perf-nightly.yml#L3-L24).
- **Fuzz and provider gaps:** PhotoCraft's libFuzzer job is manual-only, with bounded seconds and failure artifacts; the observed main run skipped it. ArtCraft's source rules describe database/provider fixture isolation and an opt-out feature for hosts without MySQL, but this research did not verify database/provider runtime. [manual fuzz lane](https://github.com/storytold/photocraft/blob/184c226a76c9ca6234d473912d438feaa48c1cb0/.github/workflows/ci.yml#L248-L293) [database/provider documented policy](https://github.com/storytold/artcraft/blob/d4e4ac69bbd93d237eaf5d0260bc6a5ff3a5e373/.claude/rules/testing.md#L5-L21).

## Bounded Nvwa adoption order

1. Add or strengthen normal-CI command/undo/export and corrupt-file checks at Nvwa's existing public boundaries. Include rejected-command state/history invariants and a small pinned original corpus.
2. Add deterministic offscreen interaction/render checks for a few meaningful controls and one scene workflow. Add an intentional regression so the assertion is known to detect the failure. Fail the required rendering lane if its renderer is unavailable.
3. Keep Linux domain/CLI tests and Wasm compilation inexpensive. Run targeted macOS/Windows native tests where OS integration is actually involved, plus a real browser acceptance lane for the Wasm product. Record separate receipts with source SHA and surface.
4. Add manual/nightly fuzz and performance lanes only when their inputs, limits and retained failure artifacts are concrete. Never list ignored, skipped or build-only checks as completed acceptance.

**VERIFIED —** pinned source and sampled public job/log evidence support the specific observations above; craft-ui visual/negative-control/docking execution was observed on three OSes, and selected PhotoCraft command/property/corruption paths on Linux/Windows. **NOT-RUN —** local third-party execution, current PhotoCraft source-head tests, ArtCraft application test execution, real browser/native acceptance, fuzz, and exhaustive platform/history/branch-protection audits.
