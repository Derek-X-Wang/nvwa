# Share Rust rendering and editing across native and Web

Use one Bevy 0.19.1 runtime and bevy_egui 0.42.0 editor, pinned with Rust 1.95.0 and Cargo.lock. Both versions were checked against their published crate metadata; a browser frontend or webview desktop shell would introduce another state and input path that this prototype does not need. The selected pair changes the scene/UI APIs from older examples, so exact-version source and actual native/Web runs are required before acceptance.

Adopt egui for M0 after actual native Metal and browser WebGPU runs. The same shared systems successfully edit parameters, switch clips and exchange documents. No equivalent Bevy UI performance comparison was executed; the completed A/B experiment compares retargeting methods instead. Keep Bevy reflection auto-registration because actual first startup panicked when GLB scene types were unregistered. Use Reinhard tone mapping to avoid a hidden default dependency on tone-mapping lookup textures.

Sources: [Bevy 0.19.1](https://docs.rs/crate/bevy/0.19.1), [bevy_egui 0.42.0](https://docs.rs/crate/bevy_egui/0.42.0). Graphical acceptance and performance are recorded separately in the test matrix. Default fonts lack CJK glyphs; native drag/clipboard and IME remain hand-test items. Benchmark mode fixes a physical1280×720 surface and continuous scheduling; it does not change normal editor scheduling. The benchmark-only HTML canvas PNG button is a file-export adapter for embedded browsers that reject the automatic Bevy download; all editing, pose and animation code remains Rust.
