# Portable documents own character state

The Rust core owns a versioned document with stable string IDs, a character profile, a recipe and animation references. Studio and the offline CLI call the same typed, atomic commands; stored JSON carries no Bevy entities or GPU handles. This costs explicit validation and runtime mirroring, but permits cross-platform work exchange without engine serialization coupling.

Use snapshot undo for this bounded single-character M0: one drag previews a validated clone and commits once, while undo/redo change the revision monotonically. Tests cover failures, idempotent retries, conflicting reuse, revisions and equivalent command paths. History and remembered command IDs remain session-local; an inverse-operation or persistent-log design was not benchmarked and is not adopted.

Bound retained session content with FIFO eviction: at most 128 total undo/redo snapshots and 16 MiB of compact document JSON, plus 1,024 successful retry records and 8 MiB of compact envelope/result tuple JSON. These are retained-payload budgets, not exact process-memory limits. Evict only farthest reachable snapshots to preserve adjacent undo/redo. An oversized adjacent snapshot clears its destination history as a barrier; an oversized retry record expires after all older entries. Valid edits still succeed. Duplicate reads do not refresh retention. Retained conflicting IDs still conflict; an expired original envelope gets `revision_conflict`, while an expired ID can be reused with the current revision and a valid command. Failed commands leave the document and retention unchanged. Saving and reopening transfers only the document, without session history. Rust constants and the CLI `describe-capabilities` response expose this policy. Evidence and reproduction: [bounded session history](../../experiments/10-bounded-history/REPORT.md).

Platform file completions distinguish `Opened(String)` from `Saved`, including empty files. Native imports cap reads at 2 MiB + 1 and reject nonregular handles; Unix opens are nonblocking so a FIFO cannot freeze the UI. Native saves use an exclusive, unique adjacent temporary file before rename. Browser file callbacks carry data through a single-flight mailbox; the browser download API confirms initiation, not a durable filesystem write.
