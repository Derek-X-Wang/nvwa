# One independent Ubuntu complete eye/hair group

This isolated orphan diagnostic package is scoped to one new-branch push, one
standard Ubuntu 24.04 x64 job, and run attempt 1. It is not normal PR or main CI.
No dependency, action, toolchain, model or material installation is permitted.

`source/` contains exactly the 601 current candidate files (59,247,541 logical
bytes), byte-for-byte equal to the passed local snapshot. The candidate base is
`eb90badc63fd12753224f1691e8a57b3848241e8`; five reviewed candidate files differ
from that base. `diagnostic/SOURCE-INVENTORY.json` fixes all candidate bytes.

The observer expands the existing eye/hair catalogue in the same order into 21
commands and 428 suite methods. The authorized `-f` is present on all twenty
unittest discovery commands. Per mode the source protocol retains the complete
509 matrix, nine legacy calls, 128 parser controls and real usage, signal and
30-second timeout controls. All 530 actual calls per mode are reconciled.

The original source timeout remains 30 seconds. One shared group deadline of
300 seconds includes logs, reconciliation, final source hashes and cleanup, with
10 seconds reserved for owned process-group cleanup. T01 retains its shared
40-second pre-admission check. Setup, including fixed Git acquisition and runner
preflight, is bounded by 120 seconds. Acquisition retains a two-second cleanup
reserve. Export has 60 seconds. The total ceiling is 900 seconds from the first
bootstrap instruction; the GitHub job also has a 15-minute timeout. Failure,
missing evidence, interruption or an unexpected timeout means STOP, without a
second attempt. The expected real T01 timeout remains a required passing control.

Only preinstalled `/usr/bin/python3` CPython 3.12.3 on Ubuntu 24.04 x64 is admitted.
The exact binary, version, image and Node binary/version are recorded. A mismatch
stops; nothing is installed. Node's actual version command is the first of the
21 commands. Source files and their subprocess code are never instrumented by
the external observer.

Acquisition uses one explicit public Git fetch of this event's exact commit and
an exact list of literal sparse paths. Git may lazily fetch the requested blobs;
there is no archive, full original repository checkout, fallback or retry. The
Git credential helper, user/system Git config and inherited proxy/token
configuration are absent in the acquisition child environment. Only acquired
paths are materialized. Each acquired file is recorded with bytes and SHA256.
The acquisition manifest omits itself and the workflow to avoid a hash cycle;
both are additionally recorded in SETUP and bound to the root's exact orphan
commit and external frozen package manifest.

`complete-ledger.json` changes only the original top-level `source_root` metadata
to `<original-local-source>`. All other JSON values and the entire ordered calls
array are unchanged. Original and derived hashes are fixed in provenance. The
unused private-path protocol document and checklist are represented by hashes.

Transport is this job's bounded lossless log envelope: at most 64 files, 4 MiB
raw, 8 MiB framed bytes, with ordered base64 chunks, lengths, SHA256s and run /
attempt / commit identity. These are new, job-specific limits, not changes to
prior evidence or acceptance limits. The root fetches only this finished owned
job's raw log, reconstructs original stdout/stderr bytes, and reconciles all raw
evidence. No artifact actions are used. A complete group requires exactly 47
transport files: 42 original streams, initial/final source hashes, final status,
setup identity and consolidated raw Git acquisition logs. Missing files remain
incomplete; the decoder does not create acceptance evidence or execute targets.

Cleanup owns only acquisition Git groups, the 21 command session/process groups,
and the diagnostic temporary directories. Test scratch cleanup remains in the
unchanged target tests. Aborts escalate only the owned group with INT/TERM/KILL.
Raw evidence and this package are retained. Local publication, remote branch,
run cancellation and terminal readback are the root's responsibility. The root
controller has one durable push barrier, at least 60 seconds between polls,
a 300-second queue admission bound, a 900-second lifetime from publication and
at most one freshly identity-checked cancellation. No rerun, repush or branch
update is permitted after this allowance is consumed.
